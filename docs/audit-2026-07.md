## Executive summary

The codebase is in genuinely good shape: mypy `--strict` and ruff are clean, the protocol client has 303 tests behind a 93% branch-coverage gate, backup filenames are regex-locked against traversal, all switch CGI parameters on the main paths are URL-encoded, sessions are signed random tokens with dual expiry, every lockout-risky write is gated behind READ_ONLY + pre-write auto-backup + typed host confirmation, the transport has **no retries** and **no redirects** (deliberately crash-safe), and the container runs non-root with clean SIGTERM handling.

The serious problems cluster in exactly one theme — **aggregate switch load** — plus one write-safety gap:

1. **The live-traffic WebSocket violates both read-safety rules.** Each connected browser tab gets its *own* backend poll loop against the switch (2 s cadence), and the frontend never closes the socket when a tab is hidden. A forgotten background port-detail tab polls the switch all night; N tabs multiply the cadence N×.
2. **The restore endpoint is the only switch write that bypasses the pre-write auto-backup** (and the typed host confirmation), contradicting the project's own write-safety policy and docstring ("Every write route in Phase 3 goes through write_with_autobackup").
3. **The Docker HEALTHCHECK transitively probes the switch every 30 s, 24/7**, via the unauthenticated, uncached `/api/v1/health` endpoint.
4. **Nothing anywhere bounds concurrency toward the switch** — opening the Configuration tab fires ~10–12 simultaneous CGI GETs; there is no semaphore, no server-side cache, no coalescing.
5. **`docker compose up` currently publishes the UI on host port 80 on all interfaces** because `${SWITCH_PORT}` (the switch's HTTP port) is reused as the host publish port, and the documented `127.0.0.1:` bind prefix was dropped.

Secondary themes: several write operations report success without checking the switch's response (including restore and device-reset), switch passwords land cleartext in Docker logs via httpx INFO logging, the README documents three safety controls that don't exist, the frontend has zero tests, there is no CI, and the backend has no lockfile.

## Critical

### C1 — Live port-traffic WebSocket keeps polling the switch while the tab is hidden
`frontend/src/api/hooks/useLivePortTraffic.ts:90-151` · effort: small · verified 3/3 (critical)

The effect opens the WebSocket on mount and closes it only on unmount/port change/manual reconnect. There is no `visibilitychange` handling anywhere in `frontend/src` (grep: zero matches). All HTTP polling correctly pauses in background via TanStack Query's default `refetchIntervalInBackground: false` — but the WS stream, the *highest-frequency* data path in the app, does not. An admin who opens a Port Detail page and switches away leaves the backend polling the physical switch at 2 s cadence indefinitely.

**Fix:** add a `visibilitychange` listener in the effect: close the socket when `document.visibilityState === 'hidden'` (optionally after a short grace period), reopen on visible — the existing `reconnect()` nonce mechanism can be reused (~15 lines). Keep the deliberate no-auto-reconnect behavior for error cases.

### C2 — One switch poll loop per WebSocket connection: N tabs multiply switch polling with no cap
`backend/app/ws/port_traffic.py:94-147` · effort: medium · verified 3/3 (critical)

Every accepted `/ws/port-traffic` connection runs its own independent `get_port_counters` loop. There is no shared poller, no fan-out, and no cap on concurrent connections. Three tabs ≈ one switch request per 0.67 s sustained — the aggressive-polling regime documented to have crashed this hardware. (Each individual loop is correctly sequential — fetch → send → sleep — so a single connection cannot stack requests; the problem is the aggregate.)

**Fix:** run **one** poller task per app (started on first subscriber, stopped on last disconnect) that polls the switch once per interval and fans the computed frame out to all connected sockets (module-level task + per-client queues). Optionally cap concurrent WS connections. Switch cost then stays at 1 request/interval regardless of client count.

### C3 — Restore writes a full config to the switch with no pre-restore backup and no host confirmation
`backend/app/api/backups.py:136-169` · effort: small · verified 3/3 (1× critical, 2× high)

`restore_backup` checks `settings.read_only`, then calls `upload_config` directly. It is the **only** write path that does not go through `write_with_autobackup` — `backend/app/write_safety.py:3` explicitly claims "Every write route in Phase 3 goes through write_with_autobackup". It also lacks `require_host_confirmation`, unlike far less dangerous writes (device-reset, IP config). Once `READ_ONLY=false` (the normal mode for config work), restoring a wrong or stale `.pcc` permanently destroys the current live config with no rollback point — the exact failure the project's backup-first rule exists to prevent. The frontend's `RestoreDialog` (typed-IP confirmation + diff preview) mitigates the confirmation gap for UI use, but nothing anywhere snapshots the live config before upload.

**Fix:** wrap the restore in `write_with_autobackup` (pre-restore snapshot, `trigger="pre-write"`; return the new `BackupMeta` so the UI can offer one-click "undo restore") and add a `confirm_switch_host` body field gated by `require_host_confirmation`, mirroring `backend/app/api/diagnostics.py:154-167`. See also H4 (restore success is never verified).

## High

### H1 — No concurrency cap or serialization toward the switch; Configuration tab fires a ~10–12-request burst
`backend/procurve_client/transport.py:40` (root cause) · `frontend/src/features/configuration/ConfigurationPage.tsx:38-50` (worst trigger) · effort: small · verified 3/3

The transport is the single choke point for all switch traffic, and it applies httpx defaults (up to 100 connections). Nothing structural prevents stacked parallel requests against the 2004-era embedded HTTP server: mounting the Configuration page fires ~10–12 near-simultaneous CGI GETs (Security page ~5), and every additional tab adds its own.

**Fix (highest-leverage single change):** pass `httpx.Limits(max_connections=1, max_keepalive_connections=1)` to the `AsyncClient` and/or an `asyncio.Semaphore`/`Lock` in `get()`/`post()` — ideally shared per switch host across all sessions, since there is one physical switch. Optionally add minimum inter-request spacing. This bounds worst-case switch pressure app-wide regardless of caller behavior. Complement with generous `staleTime` on the mostly-static configuration reads (frontend) and a small server-side TTL cache (M8).

### H2 — Docker HEALTHCHECK transitively probes the switch every 30 s, 24/7; `/api/v1/health` is unauthenticated, uncached, 1:1
`docker/Dockerfile:47` · `backend/app/api/health.py:28-30` · effort: small · verified 3/3

`healthcheck.sh` hits the local `/api/v1/health`, but that endpoint constructs a **fresh `ProcurveTransport`** (new TCP connection) and GETs `/home.html` on the switch for every call — no cache, no throttle, no auth. The container therefore probes the fragile switch every 30 s forever, independent of UI activity and of the tab-visibility pause logic; any external monitor pointed at the endpoint multiplies that 1:1.

**Fix:** make the Docker liveness path switch-free — a `/livez` that only confirms the process answers. Keep switch reachability as a separate check served from cached state with a minimum re-probe interval (15–30 s) and single-flight coalescing, and reuse one long-lived transport instead of per-call construction.

### H3 — `${SWITCH_PORT}` publishes the UI on the switch's port (host port 80, all interfaces)
`docker-compose.yml:9` · effort: trivial · verified 3/3 (1× high, 2× medium)

One variable now steers two unrelated things: the switch's HTTP port (its documented meaning, consumed by the backend via `env_file`) and the host port the UI is published on. With the shipped values (`SWITCH_PORT=80`), `docker compose up` publishes the admin UI on host port 80 on **all interfaces** — and the `127.0.0.1:` bind prefix the README still advertises twice is gone. An operator who sets `SWITCH_PORT=9090` to "move the UI" silently redirects the backend's switch connection to port 9090.

**Fix:** `- "127.0.0.1:${WEBUI_PORT:-8080}:8080"`, document `WEBUI_PORT` in `.env.example`, and leave `SWITCH_PORT` exclusively as the switch's port.

### H4 — Restore (`upload_config`) declares success on any HTTP 200 without checking the response or sanity-checking the payload
`backend/procurve_client/operations/backup.py:99` · effort: medium · verified 3/3

The firmware routinely returns 200 with an HTML error body (per `transport.py:110-113`'s own comment), so a rejected restore is reported as a clean success — the operator believes a restore happened when it did not, for the single highest-risk operation in the system.

**Fix:** (1) sanity-check the payload before upload (running-config header check via the existing parser, or printable-ASCII heuristic) unless forced; (2) parse the upload response for error sentinels/HTML error markers; (3) offer a post-restore verify: re-download via `download_config` and compare SHA-256 (accounting for the documented `\r\n` normalization). The design spec (docs/specs, §8.1/“post-restore auto-verify”) already promises this.

### H5 — README documents safety controls that do not exist
`README.md:71` (polling "paused when the tab is hidden") · `README.md:400` (CSRF "double-submit token") · README + `backend/app/settings.py:33-38` (container "refuses to start" with the example placeholder) · effort: small

Three concrete claims are false today:
- **Tab-hidden pause** — true for React Query intervals (library default), false for the WebSocket (C1).
- **CSRF double-submit token** — no CSRF token code exists anywhere in backend or frontend; the only defense is the `SameSite` cookie (see L2).
- **Placeholder secret refusal** — the validator's rejection set (`""`, `"change-me"`, `"your-secret-here"`) does not contain the actual `.env.example` value `change-me-to-a-random-string-of-at-least-32-chars`, which is ≥32 chars and passes. Anyone who copies `.env.example` runs with a publicly-known signing key.

**Fix:** implement C1's pause; add an Origin/`Sec-Fetch-Site` check on write routes (or implement the documented token) or reword the claim; reject any secret starting with `change-me` and add a test using the literal example value. Documentation that overstates safety is worse than absent documentation.

## Medium

### Switch-facing correctness

- **M1 — Most configuration writes return `ok=True` unconditionally.** `backend/procurve_client/operations/configuration.py` (9× `ConfigWriteAck(ok=True, …)` at lines 218, 263, 330, 403, 415, 552, 879, 948, 996; 7× `QosWriteAck` at 614–803) and `status.py:419/:434` (alert ack/delete) never check status or body. A rejected write — including the connectivity-critical `set_ip_config` — reads as success, so the operator's mental model diverges from switch reality. VLAN/stacking modules already parse error sentinels; these don't. *Fix:* raise `ProtocolError` on non-200 and run bodies through the shared error-line check; where the body shape is unknown, do a follow-up read.
- **M2 — CSV `indeces` parameters are sent as `%2C` while the documented wire contract requires literal commas.** `backend/procurve_client/operations/status.py:407` (alert ack/delete), `set_bobports`, `mod_ports`. The codebase already assembles URLs manually elsewhere *precisely to defeat httpx encoding* (`vlan.py:439-444`), which suggests the firmware may not percent-decode — in which case every multi-item write is silently misparsed (and M1 hides the failure). *Fix:* assemble these queries manually like `set_vlan_ports` does, or verify once against a live capture and update the docstrings; pin with a respx byte-match test.
- **M3 — `device_reset` returns `initiated=True` on any exception, including failures before the request was sent.** `backend/procurve_client/operations/diagnostics.py:170-173` catches everything `transport.get` raises (which includes pure connect errors) and reports a reboot in flight. *Fix:* only treat post-send errors (ReadError/ReadTimeout/RemoteProtocolError) as plausible reboot; re-raise AuthError and connect-phase failures.
- **M4 — WS stream is not bound to the session lifecycle.** `backend/app/ws/port_traffic.py:135` validates the cookie only at handshake: an expired session keeps streaming (and keeps polling the switch) indefinitely; logout calls `store.drop()` which closes the transport *under* the live loop, so the next poll raises an unhandled `RuntimeError`. *Fix:* re-check expiry/liveness each tick; catch `TransportError`/`RuntimeError` and close with 1008.
- **M5 — WS poll loop dies silently on switch errors.** `backend/app/ws/port_traffic.py:148-159` handles only `WebSocketDisconnect`; a transient switch hiccup permanently kills the live chart with no log and no client-visible reason. *Fix:* wrap the poll body in `try/except ProcurveError`, log, send a final error frame, close gracefully.
- **M6 — Switch passwords are written cleartext to Docker logs.** `backend/app/logging_config.py` configures INFO globally and httpx logs full request URLs at INFO; `PUT /api/v1/security/device-passwords` and stacking writes carry passwords in the query string by firmware design, so new Manager/Operator passwords persist in `docker logs`. Manager-password recovery on this hardware is a physical factory reset. *Fix:* `logging.getLogger("httpx").setLevel(logging.WARNING)` (and `httpcore`), or a redaction filter for the known credential params.

### Switch load (beyond C1/C2/H1/H2)

- **M7 — Port-detail page double-polls the same CGI.** `frontend/src/features/status/PortDetailPage.tsx:35`: the WS hits `/cgi/portc` every 2 s while `usePortCounters` also polls it every 10 s, plus `usePortStatus` every 5 s — ~0.8 req/s from one page, 90% redundant. *Fix:* derive the counters card from the WS stream (the backend already holds raw cumulative counters in `prev`), or disable the REST interval while the WS is connected.
- **M8 — No server-side cache/coalescing: every browser poll maps 1:1 onto a switch request.** `backend/app/api/status.py` and peers. A 2–5 s in-process TTL cache keyed by CGI path+params, with single-flight locking, makes N tabs cost the same as one. Pairs with H1.

### Frontend correctness

- **M9 — PortConfigTable submits a stale flow-control value its own UI shows as forced-off.** `frontend/src/features/configuration/PortConfigTable.tsx:202` sends raw `flowControl` state while the checkbox renders `effectiveFlow` (forced false for half-duplex modes) — guaranteed 422 the user cannot explain, or a bad write if backend validation ever regresses. *Fix:* submit `effectiveFlow` (one line).
- **M10 — `useLiveUptime` re-renders the whole Status dashboard at 10 Hz and drifts under background throttling.** `frontend/src/lib/utils.ts:25-33`: a 100 ms `setInterval` adding a fixed 10 cs per fire — browsers throttle hidden-tab timers to ≥1 s, so after an hour hidden the displayed uptime is ~54 min behind; meanwhile the 28-port SVG chassis and charts reconcile at 10 Hz while visible. *Fix:* anchor once (`t0 = Date.now()`) and compute elapsed in a 1000 ms tick; isolate into a tiny leaf component; `React.memo` on `SwitchSvg`/`PortUtilizationChart`. Related: alert wall-clock times anchor to a never-refreshed uptime snapshot (`frontend/src/lib/format-alert.ts:29`) — after 6 h open, every alert renders 6 h too recent.

## Low / hardening-if-exposed

**Security hardening** (all gated on LAN attacker or future exposure):
- **L1** No login rate limiting/backoff; each attempt also probes the switch (`backend/app/api/auth.py:55`). A small exponential backoff also protects the switch from probe bursts.
- **L2** CSRF/WS-hijack: `SameSite=Strict` is the only defense; Origin is never checked, and same-*site* includes other ports on the same host (a dev server on `:3000` can ride the cookie; Starlette parses JSON bodies regardless of Content-Type, so text/plain POSTs skip preflight). *Fix:* validate `Origin` on writes and the WS handshake — cheap middleware. (Related to the false README claim, H5.)
- **L3** Ping/link-test accept unbounded `packet_count`/`timeout_s` and unvalidated destination (`backend/app/api/diagnostics.py:64-77`, `operations/diagnostics.py:80`) — `packet_count=10_000_000` ties up the switch's CGI for a very long run. *Fix:* `Field(ge=1, le=999)` bounds + format regexes.
- **L4** Expired sessions leak `SessionEntry` objects + open httpx clients (holding credentials) until restart (`backend/app/auth.py:81-97`). *Fix:* lazy sweep on login/access (~5 lines).
- **L5** No security headers on the SPA (CSP, `X-Content-Type-Options`, frame protection) (`backend/app/static.py:58`). Defense-in-depth only — no XSS sink was found anywhere (no `dangerouslySetInnerHTML`/`innerHTML` in the codebase).
- **L6** `SESSION_SECRET` placeholder passes the validator (see H5) — fix the validator regardless of the README wording.
- **L7** WebManagersCard has no IPv4/mask format validation on the *authorized-managers whitelist* — the card whose own warning says a bad entry locks you out immediately (`frontend/src/features/security/WebManagersCard.tsx:35-45, 202-235`). Dialog friction exists; payload validation doesn't. Also consider warning when the new whitelist would exclude the operator's own IP.
- **L8** DevicePasswordsCard allows an operator username with no password (partial-pair submit) (`frontend/src/features/security/DevicePasswordsCard.tsx:60`).
- **L9** Login response returns the raw unsigned `session_id` in the JSON body (`backend/app/api/auth.py:76`) — drop it; the cookie is the credential.
- **L10** Stacking writes build query strings by raw f-string interpolation (`backend/procurve_client/operations/stacking.py:517`): a password/stack-name containing `&`, `=`, `#` truncates or injects parameters — a correctness bug on a write path under this threat model. *Fix:* charset validation in the models or `quote_plus` (the applet used `URLEncoder.encode`).

**Robustness / correctness:**
- **L11** Parsers raise raw `ValueError`/`ValidationError` instead of the typed `ParseError`/`SchemaError` hierarchy (`operations/identity.py:137` et al.) → users see generic 500s when the switch serves garbage.
